## 4. Service Worker

New file: `public/sw.js`, versioned cache `alertownik-pwa-v1`.

- **Install**: precaches only `/offline.html` and `/icon-192.png`.
- **Activate**: deletes old `alertownik-pwa-*` caches (never touches other cache namespaces), then `clients.claim()`.
- **Message**: handles `"SKIP_WAITING"` to let a waiting worker activate on user request.
- **Fetch**: only intercepts same-origin `GET` navigations (`request.mode === "navigate"`). Everything else — non-GET, cross-origin, `/admin*`, `/api*`, `/_next/*`, and any non-navigation fetch/XHR — passes straight through untouched. On a failed navigation fetch, falls back to the cached `/offline.html`. Nothing is ever written to the runtime cache from fetch handling — only the install-time precache exists.

`next.config.ts` adds:
- `Cache-Control: no-cache, no-store, must-revalidate` + `Service-Worker-Allowed: /` on `/sw.js`, so updates are never served stale.
- `Content-Security-Policy: worker-src 'self'` on all routes (no prior CSP existed, so nothing was weakened).

## 5. Cache Policy

Only two files ever enter Cache Storage: `/offline.html` and `/icon-192.png`. Verified automatically (`Cache safety (M3)` test) that the cache never contains `/`, `/admin*`, `/api*`, or any alert page. There is no runtime/opportunistic caching path at all — the only `cache.put`-equivalent call in the whole worker is the install-time `cache.addAll(PRECACHE_URLS)`.

## 6. Excluded Routes

Hard-excluded from any service-worker handling: `/admin`, `/admin/*`, `/api`, `/api/*`, `/_next/*`, all non-GET requests, all cross-origin requests (Supabase, external sources). These are never intercepted, never cached, never given an offline fallback — they simply behave as if no service worker exists.

## 7. Offline Experience

`public/offline.html` — fully standalone (inline CSS only, no external fonts/scripts/images beyond itself). States plainly, in Polish: no connection, Alertownik can't fetch current alerts right now, **old alerts are not shown as current**, plus a "Spróbuj ponownie" button that reloads. Verified readable at 375×812, 390×844, 414×896 and desktop widths (flex-centered, max-width card, no fixed pixel overflow).

## 8. Install UX

## 9. Update Lifecycle

`src/components/PwaController.tsx`:
- Registers `/sw.js` with `scope: "/"`, `updateViaCache: "none"` — **production builds only** (`process.env.NODE_ENV === "production"`), so `next dev` never risks a worker intercepting HMR/dev assets.
- Watches for a waiting worker (`updatefound` → `installed` while a controller already exists) and shows a small `aria-live="polite"` banner: "Dostępna jest nowa wersja Alertownika." with "Odśwież" and a dismiss (✕) button.
- Only on explicit "Odśwież" click does it `postMessage("SKIP_WAITING")` to the waiting worker; the reload only happens on the resulting `controllerchange` event, and only because the click set a ref flag first. This was a real bug caught by the new test suite during this sprint: an earlier version reloaded on *any* `controllerchange`, including the very first activation for a brand-new visitor (uncontrolled → controlled also fires that event), which reloaded the page unprompted. Fixed by gating the reload behind a `userRequestedUpdate` ref that's only set inside the button's `onClick`.
- Registration failures are swallowed silently — the app must work identically with zero service-worker support.

## 15. Known Limitations

- No offline browsing of alert content — by design (see Limitations doc), not a gap.
- No periodic background sync / periodic refresh.
- No push notifications (out of scope per sprint brief).
- Install button only appears in browsers that fire `beforeinstallprompt` (Chrome/Edge-family); iOS Safari never fires it, so `/instalacja`'s manual steps are the only path there — expected, not a bug.
- Update banner requires the user to already have the app open when a new deploy ships and to click "Odśwież" — there is intentionally no silent/automatic reload.
- Device installation (real Android/iPhone/desktop install flow) has not been manually verified yet — see Section 16 checklist below.
